## Findings

### Critical
1. **Bare-id vs full-key inconsistency across T51/T53 vs T46/T50/read surfaces.**
   `build_path_to_id_map` (references.py:109) emits bare `generate_artifact_id` output,
   and both skills instruct storing that bare id in `references` and rewriting content to
   `arkeology://artifact/{bare-id}`. But every consuming surface addresses artifacts by full
   S3 key `{write_prefix}/{id}{ext}` (write.py:377; read.py:78 scope gate;
   resources.py:501 arkeology:// resource; _search_helper.py find_referrers `$eq`; delete
   tests seed full keys). Migration-produced references are dead links and invisible to
   the D13 referenced_by warning.
2. **AC-58 Story 1 (`../decisions/B.md`) cannot resolve anywhere in the delivered flow.**
   references.py declares relative joining the skill's responsibility; the migration
   skill (SKILL.md:265) explicitly instructs leaving `../` entries unresolved; the
   backfill skill has no joining step either. The spec's P1 example fails end-to-end.

### Major
3. `build_path_to_id_map` does not normalize its keys — `./`- or backslash-prefixed
   manifest paths never match any normalized reference (one-sided canonicalization).
4. `_read_link_fields_for_reindex` (reconcile.py:54) swallows `CredentialError`,
   inconsistent with the four surrounding phase handlers that abort with a structured
   credential error; a mid-run credential failure yields a "successful" reconcile with
   link fields silently stripped from vector metadata, unrepaired by future runs.
5. Spec-required integration test (`tests/integration/test_tools_reconcile.py`
   annotation-restoration case) is missing from the branch.
6. write.py Step 4a merges read-forward link fields into `vector_metadata` *after* the
   Step 3c `check_metadata_budgets` call — merged lists can breach the 2 KB filterable
   budget unchecked, producing the partial-write mode the budget check exists to prevent.
7. Backfill skill Step 5 existence cross-check compares bare map ids against full-key
   `list_artifacts` output — literal execution proposes zero candidates (silent no-op).

### Minor
8. `_URL_PREFIXES` check is case-sensitive (`HTTPS://…` misreported as unresolved path).
9. `generate_artifact_id` reimplemented in two SKILL.md scripts with no drift test,
   despite references.py's "do not reimplement" docstring.
10. Skill script omits type/date validation that `generate_artifact_id` enforces.
11. Duplicate manifest paths silently last-win in `build_path_to_id_map`.
12. `read_link_annotations` uses two GETs (no `list_object_annotations`) — cheaper than
    the spec wording, functionally equivalent; +2 S3 GETs per re-indexed artifact only.
13. Overwrite read-forward sources vectors only; if vectors are absent (partial-write
    state) annotation link trail is lost on overwrite (ADR-sanctioned source choice).

### Spec Alignment
- T48: all unit-test ACs implemented and passing; response schema unchanged; scope gate
  intact; Phase 3 correctly untouched (no re-index there). Integration AC missing (F5).
- T51: helpers + normalization ceiling + URL passthrough + forward reference + fall-through
  all implemented and tested; Story 1 broken by F1/F2; report flow present in skill.
- T53: dry-run-first, batch approval, link_metadata-only, never-rewrites-content,
  advisory-only in-body links, missing-manifest fallback — all present; F7 blocks efficacy.
- T54: implemented on main (search.py:160–188) with all four spec tests; this branch only
  renumbers the test header. Compliant (synthesise correctly untouched).

## Recommendations
Resolve the canonical `references` id format (architect decision) before merge; add
relative-path joining to both skills; normalize map keys; re-raise CredentialError in the
reconcile annotation read; re-run the budget check after the Step 4a merge; add the
missing integration test. Not merge-ready until F1/F2 are resolved.
