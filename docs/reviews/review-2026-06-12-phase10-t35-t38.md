**M1 — `write.py` docstring: `commit_refs` absent from Args; Returns stale**

`write_artifact` (line 126–148) accepts a `commit_refs: list[str] | None = None` parameter
that is not listed in its Args docstring. The Returns section also says:

```
On success: ``{"artifact_id": str, "sections_indexed": int}``
```

but the actual success dict now also includes `"last_edited_ulid": str` (line 520).

Fix:
```python
# In Args:
commit_refs: Optional list of git commit SHAs to pre-link this artifact.

# In Returns:
On success: ``{"artifact_id": str, "sections_indexed": int, "last_edited_ulid": str}``
```

---

**M2 — `artifact.py` Artifact model docstring: `commit_refs` absent from Attributes**

The `Artifact` class docstring (lines 148–165) lists all existing attributes but omits the
newly added `commit_refs` field.

Fix — add to the Attributes section:
```
commit_refs: Optional list of git commit SHAs linked to this artifact.
```

---

**M3 — `test_tools_propose_commit_links.py` `_seed_standard`: seeds `"commit_refs": []` instead of omitting the key**

`_seed_standard` (lines 84, 96, 120) seeds unlinked artifacts with `"commit_refs": []`
directly in vector metadata. In production, `write_artifact` with `commit_refs=[]` omits
the `commit_refs` key from vector metadata entirely (per the T36 spec: "S3 Vectors rejects
empty arrays — omit key"). The test seeds a condition that would be rejected by the real
S3 Vectors API.

The implementation handles both cases correctly (absent key → `meta.get("commit_refs")`
returns `None`; empty list → `isinstance([], list)` → `commit_refs_val = []`). A separate
test (`test_missing_last_edited_ulid_yields_null_fields_and_is_candidate`) does cover the
absent-key case. The test still exercises the right behavior.

Fix: remove `"commit_refs": []` from the seed metadata in `_seed_standard` (omit the key
entirely) and add an explanatory comment explaining that production always omits this key
when empty:
```python
# No 'commit_refs' key — production write_artifact omits it when empty
```

---

**M4 — Missing test: legacy artifact (no `last_edited_ulid`) excluded when `since_ulid` provided**

There is a test (`test_missing_last_edited_ulid_yields_null_fields_and_is_candidate`)
verifying that a legacy artifact appears as a candidate when `since_ulid` is *absent*.
There is no corresponding test verifying that a legacy artifact is *excluded* when
`since_ulid` is provided. Since `filter.py`'s `$gte` returns `False` for a `None` field
value, this is the correct behaviour — but it is not directly asserted.

Fix: add a test case to `test_tools_propose_commit_links.py`:

```python
async def test_legacy_artifact_excluded_when_since_ulid_provided(
    monkeypatch, vectors_client_2
) -> None:
    """Legacy artifact (no last_edited_ulid) is excluded when since_ulid is given."""
    settings = _make_settings(monkeypatch)
    # Seed one ULID_HIGH artifact and one legacy artifact (no last_edited_ulid)
    vectors_client_2.put_vector(
        "artifacts/legacy#summary",
        _unit_vec(0.5),
        {**_BASE_META, "artifact_id": "artifacts/legacy", "title": "Legacy"},
        # no last_edited_ulid
    )
    vectors_client_2.put_vector(
        "artifacts/modern#summary",
        _unit_vec(0.6),
        {**_BASE_META, "artifact_id": "artifacts/modern",
         "last_edited_ulid": ULID_HIGH, "title": "Modern"},
    )

    result = await propose_commit_links(
        settings=settings, s3=None, vectors=vectors_client_2, bedrock=None,
        commit_sha=COMMIT_SHA, since_ulid=ULID_MID,
    )

    ids = [e["artifact_id"] for e in result["proposed"]]
    assert "artifacts/legacy" not in ids   # excluded: no ULID → fails $gte
    assert "artifacts/modern" in ids       # included: ULID_HIGH >= ULID_MID
```
