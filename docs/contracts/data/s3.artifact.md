# s3.artifact

## Scope

The S3 object is the artifact's **authoritative durable store**: the only place its content exists,
and the store every other representation is rebuilt from. S3 Vectors holds a searchable projection
(`s3vectors.artifact`) and the object's own annotations hold the link fields
(`s3-annotations.artifact`); either can be reconstructed from here, and neither can reconstruct
this.

## Symbols

### generate_artifact_id

```python
def generate_artifact_id(*, tier: int, type: str, date: str, title: str) -> str: ...
```

**Errors**

- `ValueError` — raised when `title` exceeds `TITLE_MAX_LENGTH` (256) or contains a Unicode
  category `Cc` control character.

**Invariants**

- Fully deterministic. The same inputs always produce the same string; no randomness, no UUID, no
  clock read.
- Tier 2 produces `{type_slug}-{date}-{title_slug}-{hash}`; tier 3 produces
  `{type_slug}-{title_slug}-{hash}`. Tier 3 excludes the date deliberately so a living document's
  key is stable across updates.
- `hash` is a deterministic 8-hex-character SHA-256 prefix of the **full, original** title, and is
  **always** appended — not only on detected collision. This is what structurally eliminates the
  three historical collision classes: titles with no Latin or digit content (which all slugified to
  the constant `"artifact"`), titles differing only past the 60-character truncation point, and
  titles differing only in punctuation the slug normalisation strips.
- Equal output implies equal `(tier, type, date, title)` inputs.

**Preconditions**

- `type` must be a member of `ARTIFACT_TYPES`, which is the single source of truth for valid types.
- `tier` must be 2 or 3.

**Postconditions**

- The returned id is URL-safe and contains no path separator.
- The id is derived from the raw title, upstream of any metadata transport encoding — the encoding
  applied to stored metadata never affects the id.

### encode_metadata_value

```python
def encode_metadata_value(value: str) -> str: ...
```

**Errors**

None.

**Invariants**

- Percent-encodes every character outside the printable-ASCII-minus-percent safe set — non-ASCII
  text, control characters, and a literal `%` — as its UTF-8 byte sequence in `%XX` form.
- Lossless and fully reversible. No content is ever silently discarded. This replaced an earlier
  NFKD-ASCII-strip that destroyed non-Latin titles.
- Output is ASCII-only and safe to transmit as an HTTP header value, which is how S3 carries
  user-defined object metadata.

**Preconditions**

- None.

**Postconditions**

- `decode_metadata_value(encode_metadata_value(v)) == v` for every `str` `v`.

### decode_metadata_value

```python
def decode_metadata_value(value: str) -> str: ...
```

**Errors**

None.

**Invariants**

- Exact inverse of `encode_metadata_value`.
- A plain string containing no `%XX` escapes passes through unchanged, so it is safe to apply to
  values written before the encoding existed.

**Preconditions**

- None.

**Postconditions**

- Every read path that surfaces a title sourced from S3 object metadata applies this, so
  `read_artifact` and `search_artifacts` can never disagree about a title.

### check_metadata_budgets

```python
def check_metadata_budgets(
    s3_metadata: dict[str, str],
    vector_metadata: dict[str, Any],
) -> None: ...
```

This symbol validates the write-path payload for **both** durable stores, so it is homed here — in
the authoritative store's contract — rather than duplicated into `s3vectors.artifact`. The three
budgets it enforces are documented per-store: the S3 aggregate below, the two vector budgets in
`s3vectors.artifact`.

**Errors**

- `MetadataTooLargeError` — raised when the S3 aggregate, the vector filterable subset, or the full
  vector metadata breaches its respective budget. Carries `budget`, `actual_bytes`, and
  `max_bytes`.

**Invariants**

- Representation-driven, never field-list-driven. It measures the **actual assembled dicts about
  to be written**, so it stays correct when a field later moves between stores.
- Returns `None` on success; it is a guard, not a transformer. It never mutates or truncates its
  arguments.

**Preconditions**

- `s3_metadata` values must already be transport-encoded exactly as they will be transmitted —
  passing raw values under-measures the real payload.
- Must be called **before** any `head_object` / `put_object` / `put_vectors_batch` call and before
  any failure-log append.

**Postconditions**

- A breach leaves no trace: no storage write to either store, and no failure-log entry. This is
  what prevents the deterministic partial-write and reconcile-replay loop the guard exists to stop.
- Where a tier-3 overwriting write's read-forward merge enlarges `vector_metadata` after the first
  call, the check must be re-run against the enlarged dict before any write. Only `commit_refs` can
  enlarge it; `references` has replace semantics and no longer merges.

## Storage Shape

**Key** — `{write_prefix}/{artifact_id}{file_extension}`, where `file_extension` defaults to `.md`.
The `write_prefix` segment is the writing server's own scope; every scope membership test is
`artifact_id.startswith(scope + "/")`, never a bare `startswith(scope)`.

**Body** — the artifact's Markdown content, verbatim. `##` headings partition it into sections for
section-level embedding; content with no `##` heading is treated as a single section.

**User-defined object metadata** — all values are strings, per the S3 API.

Two transforms apply, in order, and they are independent:

1. **List serialisation** — a list-valued field is comma-joined into a single string first. The
   payload format has no escaping, so no element may contain a comma.
2. **Transport encoding** — `encode_metadata_value` (percent-encoding) is then applied
   **uniformly to every value in the dict, without exception**, because S3 user metadata travels
   as HTTP headers, which are ASCII-only and reject raw control characters. A reader must apply
   `decode_metadata_value` to **every** value, not only to the free-text ones: a `team` of
   `Zürich` is stored as `Z%C3%BCrich`. Values that happen to be pure safe-set ASCII pass
   through both directions unchanged, which is why the encoding is easy to miss.

The `Serialisation` column below therefore records only step 1. Step 2 applies to every row.

| Key | Serialisation | Notes |
|---|---|---|
| `type` | scalar | Member of `ARTIFACT_TYPES` |
| `team` | scalar | |
| `project` | scalar | |
| `tier` | scalar | Stringified integer — **not** an int, unlike the vector copy |
| `date` | scalar | |
| `status` | scalar | `active` or `inactive` |
| `title` | scalar | Free text; the row most likely to carry `%XX` escapes in practice |
| `visibility` | scalar | |
| `tags` | comma-joined list | Single string, **not** a list, unlike the vector copy |
| `author_role` | scalar | Empty string when unset, never absent |
| `description` | scalar | Free text; as `title` |
| `source_artifacts` | comma-joined list | Single string |
| `last_edited_ulid` | scalar | Regenerated on every write |

Never present: `commit_refs`, `references`. Both moved to the object's annotations; see
`s3-annotations.artifact`.

**Budget** — `S3_USER_METADATA_MAX_BYTES` = 2048, measured as the sum over the dict of each key's
UTF-8 byte length plus each transport-encoded value's UTF-8 byte length.

## Compatibility Guarantees

- The key scheme may not be altered. Ids are fully deterministic from artifact attributes; a random
  or UUID key is never generated. The 8-hex hash suffix may never be dropped or made conditional —
  it is load-bearing against three collision classes, each of which silently destroyed artifacts.
- Artifact content lives here and only here. It may never be stored in S3 Vectors metadata.
- `tier` stays a stringified integer in this store and an `int` in vector metadata. `tags` and
  `source_artifacts` stay comma-joined strings here and `list[str]` in vector metadata. Both pairs
  are intentionally different representations — required by the S3 API on this side, required for
  `$eq` element-in-list filtering on the other. Neither is being migrated toward the other, and
  they must not be unified.
- A reader must tolerate a metadata value with no `%XX` escapes; the decode is a no-op on values
  written before the encoding shipped.
- A reader must tolerate `commit_refs` in object metadata on artifacts written before the
  annotation split, and must not treat its absence as data loss.
- A write whose generated key already exists is rejected with `validation_error` unless the caller
  passes an explicit `overwrite` flag. The guard is atomic — `put_object` uses `IfNoneMatch: "*"`
  when `overwrite=False` — so two concurrent creates cannot both succeed. Silent
  overwrite-by-collision may never be reintroduced; for a store whose purpose is never losing
  memory it is the worst available failure mode.
- Overwriting an object **wipes its annotations**. Any change to the write path must preserve the
  read-forward that re-applies the link fields after an overwriting `put_object`, or a tier-3
  living-document update silently loses them.
- This store is the rebuild source of record: `reconcile_index` can reconstruct the entire vector
  index from these objects. The reverse does not hold.
