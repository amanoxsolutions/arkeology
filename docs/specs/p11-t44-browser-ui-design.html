Architecture Decision Record

FastMCP as the MCP Server Framework

tier 3 · shared 2026-05-29 team / cairn-mcp status: accepted

Context

The project needed a Python library to host the Model Context Protocol server. Implementing the protocol from scratch requires handling connection lifecycle, JSON-RPC dispatch, schema exposure, and transport management before any tool logic can be written.

Decision

We chose fastmcp as the MCP server framework. Tool functions are registered via @_app.tool() inside register_tools() in server.py.

Alternatives Considered

OptionProsCons
fastmcp ✓ Minimal boilerplate; automatic JSON schema; built-in stdio Young library; full args logged at DEBUG
Official mcp SDK Closer to the protocol specification More boilerplate; manual schema wiring
Custom JSON-RPC Complete control; no third-party dependency Large upfront cost; duplicates solved problems

Consequences

Tool registration is concise. The fastmcp.* logger hierarchy is unconditionally clamped to WARNING in __main__.py to prevent artifact content from appearing in logs.
